# Ghostwriter — автопостинг в Threads

Сервис для управления публикациями в Threads: пользователь заранее готовит
очередь постов в **Telegram-боте**, общий планировщик публикует их по одному,
а **ИИ-Автор** по запросу генерирует новые тексты и отдельные перефразированные
варианты.

- FIFO-очередь нескольких готовых постов с редактированием через Telegram.
- `/multipost` — один промпт через несколько ИИ-моделей: сравнение вариантов и
  отправка лучшего в очередь.
- Публикация по общему расписанию, с подтверждением или сразу (настраивается).
- Один слот берёт один готовый пост; пустой слот пропускается без вызова LLM.
- Метрики каждого опубликованного поста подтягиваются из Threads API каждые 6 часов.
- Долгоживущий токен получается и продлевается автоматически.
- Сухой режим — полный сценарий без реальной публикации.
- Один процесс, SQLite, без внешних зависимостей.

---

## 1. Как это устроено

```
                ┌──────────────────── Telegram-бот ────────────────────┐
                │ /queue  /post  /pending  кнопки управления постами  │
                └─────────────────────────┬────────────────────────────┘
                                          │
  Планировщик ──► FIFO-очередь ──► согласование ──► Threads API
       │                 │                                  │
       │                 └── один готовый пост на слот       ▼
       │                                          Threads Insights
       │                                                   │
       └── пустая очередь: пропустить слот       метрики ◄─┘

  Пользователь ──► Автор (LLM) ──► новый пост или отдельный вариант ──► очередь
```

Готовые тексты добавляются через `/queue`, в том числе сразу несколько за одно
сообщение. Они хранятся в SQLite и обрабатываются сверху вниз. Планировщик сам
контент не генерирует: если очередь пуста, очередной слот просто пропускается.
При `auto_approve=false` взятый пост приходит в Telegram на согласование, а при
`auto_approve=true` сразу публикуется.

**Автор** вызывается только явно: `/post [тема]` создаёт новый текст, а кнопка
перефразирования в очереди создаёт ещё один самостоятельный пост, не изменяя
исходник. Автор учитывает тональность, аудиторию, знания проекта и последние
тексты. Лимит Threads — 500 байт UTF-8, где эмодзи обычно занимает 4 байта.

## 2. Как получить ключ API Threads

Ключ — это пара **App ID** и **App Secret** вашего приложения Meta плюс
access token пользователя, который выдаётся после авторизации. Токен сервис
получит сам — от вас нужны ID и Secret.

### 2.1. Создать приложение

1. Зайдите на <https://developers.facebook.com/apps> под своим Facebook-аккаунтом,
   к которому привязан Threads.
2. **Create app** → выберите use case **Access the Threads API**
   (если такого нет — создайте пустое приложение и добавьте продукт Threads API).
3. Укажите название приложения и контактный email.

### 2.2. Настроить права

В приложении: **Use cases → Customize** (или **Permissions**):

| Право | Зачем |
| --- | --- |
| `threads_basic` | обязательно, не удаляется |
| `threads_content_publish` | публикация постов |
| `threads_manage_insights` | чтение метрик |

Добавьте последние два кнопкой **Add**.

### 2.3. Взять ID и Secret

**App settings → Basic**:

- **Threads App ID** → в `THREADS_APP_ID`
- **Threads App secret** → в `THREADS_APP_SECRET`

### 2.4. Прописать Redirect URI

В **Use cases → Threads API → Settings → Client OAuth Settings** добавьте
**Valid OAuth Redirect URIs**:

```
https://ВАШ-ДОМЕН/auth/threads/callback
```

Требования:

- адрес должен быть **HTTPS** (localhost допускается для отладки);
- совпадать с `THREADS_REDIRECT_URI` в `.env` **символ в символ**, включая
  схему, порт и отсутствие/наличие завершающего слэша;
- Meta иногда сама дописывает слэш к URI — проверьте список после сохранения.

Там же при желании заполните **Deauthorize callback URL**
(`https://ВАШ-ДОМЕН/deauthorize`) и **Data Deletion Requests URL**
(`https://ВАШ-ДОМЕН/data-deletion`) — сервис эти эндпоинты уже реализует.

### 2.5. Добавить себя тестировщиком

Пока приложение не прошло App Review, постить можно **только от имени
Threads-тестировщиков вашего приложения**:

**App roles → Roles → Add People → Threads Tester** → добавьте свой аккаунт.
Затем в приложении Threads (мобильном) примите приглашение:
**Settings → Account → Website permissions → Apps and websites**.

Для личного аккаунта публиковать приложение в продакшн и проходить App Review
не обязательно — Development mode достаточно.

### 2.6. Подключить аккаунт

1. Запустите сервис, заполнив `.env`.
2. В Telegram-боте выполните `/token` — он пришлёт ссылку вида
   `https://ВАШ-ДОМЕН/auth/threads?key=...`.
3. Откройте её, разрешите доступ. Сервис сам:
   - обменяет `code` на короткоживущий токен,
   - обменяет его на **долгоживущий (60 дней)**,
   - сохранит токен, `user_id` и `username`,
   - пришлёт подтверждение в Telegram.

Продление: задача в 04:10 раз в сутки обновляет токен, когда до истечения
остаётся меньше 10 дней. Вручную токен можно задать и так:
`/token <access_token> <user_id>`.

> Если сервис стоит за прокси — ссылка `/auth/threads` должна открываться
> снаружи. `PUBLIC_BASE_URL` используется в ссылке авторизации.

## 3. Быстрый старт

### Windows

```powershell
cd C:\Users\admin\Documents\ghostwriter
copy .env.example .env      # заполните значения
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m app.main
```

### Linux / macOS

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # заполните значения
python -m app.main
```

Проверка: `curl http://localhost:8080/health`.

Минимально для запуска нужны: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_IDS`,
`LLM_API_KEY`, `THREADS_APP_ID`, `THREADS_APP_SECRET`, `PUBLIC_BASE_URL`.
Без `THREADS_ACCESS_TOKEN` сервис поднимется и будет ждать авторизации.

При первом `/start` бот покажет ваш Telegram ID — впишите его в
`TELEGRAM_ADMIN_IDS` и перезапустите сервис. Доступ другим пользователям закрыт.

## 4. Выбор модели (LLM)

Провайдер задаётся `LLM_PROVIDER` и `LLM_BASE_URL` — поддерживается любой
OpenAI-совместимый API и нативный Anthropic.

| Провайдер | `LLM_BASE_URL` | Модели |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` / `gpt-4o` |
| OpenRouter | `https://openrouter.ai/api/v1` | любая из каталога |
| Ollama (локально) | `http://localhost:11434/v1` | `llama3.1`, `qwen2.5` |
| Anthropic | `https://api.anthropic.com`, `LLM_PROVIDER=anthropic` | `claude-sonnet-5-5`, `claude-opus-5-5` |

Модель Автора можно менять без перезапуска через `/model writer ID_модели`
или `/set writer_model ...`.

### Мультипост: один промпт через разные модели

Сначала задайте список моделей командой `/models`:

```text
/models add anthropic/claude-sonnet-5.5, openai/gpt-4o-mini, deepseek/deepseek-chat
/models            # показать список
/models remove #2  # убрать модель по номеру
/models set model-a, model-b
/models clear
```

Затем отправьте один промпт — каждая модель получит одинаковый запрос и напишет
свой вариант поста на русском языке:

```text
/multipost Почему автоматизация не заменяет эксперта
```

Варианты приходят отдельными сообщениями с длиной в байтах. Под каждым есть
кнопки **📥 В очередь**, **🚀 Опубликовать** и **🗑 Удалить**. В очередь можно
отправить несколько вариантов — они уйдут в разные слоты расписания.

Все модели должны быть доступны на текущем `LLM_BASE_URL`. Удобно использовать
агрегатор (например, Polza.ai или OpenRouter), где одним ключом доступны модели
разных провайдеров. Список хранится в настройке `multipost_models`.

## 5. Команды бота

| Команда | Действие |
| --- | --- |
| `/post [тема]` | разово сгенерировать пост Автором по указанной теме |
| `/multipost [промпт]` | один промпт через все модели из `/models`, варианты на русском |
| `/models` | список моделей для мультипоста; `add`, `remove`, `set`, `clear` |
| `/queue` | открыть FIFO-очередь готовых постов: добавить, изменить, перефразировать, удалить или опубликовать сейчас |
| `/author` | настроить модель, голос, аудиторию, CTA и системный промпт Автора |
| `/pending` | посты, ждущие подтверждения |
| `/memory` | добавить, изменить, отключить или удалить знания о проекте |
| `/stock` | состояние постоянного медиастока и управление ротацией |
| `/menu` | показать все команды; Telegram также держит постоянную кнопку «Меню» |
| `/help` | открыть мобильную страницу со справкой, поиском и примерами |
| `/status` | состояние, лимиты, расписание, токен |
| `/analytics` | топ постов по вовлечённости + метрики аккаунта |
| `/frequency 3` | задать число публикаций в день (1–10) |
| `/frequency 4 10:00 20:00` | задать частоту и дневное окно |
| `/jitter 10` | случайный сдвиг каждого слота на ±10 минут |
| `/schedule 09:00,13:00,19:00` | вручную изменить базовые слоты |
| `/auto on\|off` | публиковать сразу / с подтверждением |
| `/pause`, `/resume` | остановить / возобновить |
| `/dryrun on\|off` | сухой режим |
| `/settings`, `/set ключ значение` | настройки без перезапуска |
| `/token` | ссылка для подключения Threads |
| `/logs` | последние события |

Под постом на согласование: **✅ Опубликовать**, **🔄 Переписать**,
**✏️ Доработать** (бот спросит, что изменить, и перепишет),
**🚫 Пропустить**.

`/queue` открывает очередь готовых постов. Для массового добавления отправьте
несколько текстов одним сообщением, разделив их отдельной строкой `---`:

```text
Первый пост
---
Второй пост
---
Третий пост
```

Для каждой записи доступны изменение текста, немедленная публикация, удаление и
перефразирование. Автор может учесть дополнительное пожелание, например «короче
и динамичнее». Результат сохраняется новым постом в конце очереди, а исходник
остаётся без изменений.

`/author` открывает панель настройки единственного ИИ-агента. Изменения пишутся
в SQLite и применяются к следующей генерации или перефразированию без
перезапуска.

Кнопка **«Системный промпт»** показывает полный действующий system-промпт.
Отправьте полный новый текст (до 4000 символов): он **заменит** базовую
инструкцию, а не добавится к пользовательскому сообщению. Промпт применяется
к `/post`, `/multipost`, доработке и перефразированию, включая повторные запросы.
Включите в него требование отвечать JSON с полями `text` и `topic_tag`.
В режиме редактирования `/reset` возвращает исходный промпт, `/cancel` отменяет
изменение. Вне панели: `/reset writer_system_prompt`.

Ниша, тональность, аудитория, память проекта и недавние посты остаются отдельным
контекстом в user-сообщении. Старое поле `writer_instructions` больше не используется;
при необходимости перенесите его содержимое в новый системный промпт.

### Случайное время и частота

Планировщик не публикует строго в базовое время. Для каждого ежедневного
срабатывания он выбирает новый случайный момент в диапазоне
`базовый слот ± posting_jitter_minutes` (по умолчанию ±10 минут).

Команда `/frequency N` равномерно строит N базовых слотов внутри окна
`posting_window_start`–`posting_window_end` и синхронизирует дневной лимит.
Например, `/frequency 5` при окне 09:00–19:00 создаст базу
09:00, 11:30, 14:00, 16:30 и 19:00; фактическое время каждого слота будет
случайным. `/frequency 4 10:00 20:00` одновременно меняет окно.

`/jitter 0` отключает случайность, `/jitter 10` возвращает разброс ±10 минут.
В каждый случайный слот берётся один готовый пост из начала очереди. Если
`/auto off`, он приходит на согласование; для публикации без подтверждения нужен
`/auto on`. При пустой очереди слот пропускается, LLM не вызывается.

### Память о проекте

Команда `/memory` открывает редактируемую базу знаний. Записи хранятся в
SQLite и переживают перезапуски. Через кнопки Telegram можно добавить запись,
изменить её целиком, временно отключить или удалить с подтверждением.

Активные записи автоматически включаются в запросы Автора при генерации,
редактировании и перефразировании. Общий контекст ограничен 12 000 символами,
чтобы расходы на LLM не росли бесконтрольно.

При запуске бот регистрирует нативный список команд Telegram и постоянную кнопку
**«Меню»** в поле ввода.

### Постоянный медиасток

Отправьте Telegram-боту JPEG или PNG (до 8 МБ) как фото или документ.
Файл сохраняется в `data/stock`, регистрируется в SQLite и автоматически
прикрепляется к следующему новому посту. Изображения выбираются по кругу:
сначала наименее использованные. Они не удаляются после публикации.

- `/stock` — количество и последние изображения;
- `/stock on|off` — включить или выключить автоматическую подстановку;
- `/stock disable ID` — временно убрать изображение из ротации;
- `/stock enable ID` — вернуть его в ротацию.

Threads скачивает файл через публичный неизменяемый URL `/media/stock/{token}`.
Ежедневный backup копирует каталог медиастока в `backups/stock`.

## 6. Ключевые настройки

Все параметры можно менять из бота через `/set`, они пишутся в БД и
применяются без перезапуска (кроме `TELEGRAM_*` и `THREADS_APP_*`).

| Ключ | Смысл | По умолчанию |
| --- | --- | --- |
| `auto_approve` | публиковать без подтверждения | `false` |
| `paused` | пауза автопостинга | `false` |
| `dry_run` | не отправлять в Threads | `false` |
| `posting_times` | базовые слоты публикации | `09:00,13:00,19:00` |
| `posting_jitter_minutes` | случайный сдвиг каждого слота ±N минут | `10` |
| `posting_window_start`, `posting_window_end` | окно команды `/frequency` | `09:00`, `19:00` |
| `max_posts_per_day` | дневной предохранитель | `10` |
| `min_minutes_between_posts` | минимальный интервал | `60` |
| `stock_images_enabled` | автоматически добавлять изображения из медиастока | `true` |
| `brand_niche`, `brand_voice`, `brand_audience`, `brand_cta` | описание бренда | — |
| `forbidden_topics` | чего не касаться | — |
| `max_post_chars` | лимит приложения (1..1500 байт UTF-8) | `500` |
| `writer_model` | модель Автора | `deepseek-chat` |
| `multipost_models` | модели для `/multipost` (через запятую) | пусто |
| `writer_system_prompt` | полный системный промпт Автора | встроенная базовая инструкция |
| `llm_temperature` | креативность Автора | `0.8` |

## 7. Деплой на сервер

Сервису нужен постоянно работающий хост с **HTTPS**: Meta не примет
`http://`-адрес в OAuth redirect (кроме localhost), а Telegram-бот должен быть
онлайн постоянно.

### Вариант А — Ubuntu/Debian + systemd + Caddy (рекомендуется)

На сервере должен быть домен, A-запись которого указывает на его IP.
Из локального каталога проекта:

```bash
# 1. Собрать архив без .venv, .env и базы
tar --exclude='./.venv' --exclude='./data' --exclude='./.env' \
    --exclude='*/__pycache__' --exclude='.pytest_cache' --exclude='.ruff_cache' \
    -czf /tmp/ghostwriter.tar.gz .

# 2. Залить на сервер
scp /tmp/ghostwriter.tar.gz root@ВАШ_IP:/tmp/

# 3. Распаковать и запустить установку
ssh root@ВАШ_IP
mkdir -p /root/ghostwriter && tar -xzf /tmp/ghostwriter.tar.gz -C /root/ghostwriter
cd /root/ghostwriter
DOMAIN=bot.example.com EMAIL=you@example.com bash deploy/deploy.sh

# 4. Заполнить секреты
nano /opt/ghostwriter/.env
systemctl restart ghostwriter
journalctl -u ghostwriter -f
```

Скрипт `deploy/deploy.sh` ставит Python, создаёт пользователя, venv,
systemd-сервис и Caddy с автоматическим сертификатом Let's Encrypt.
Повторный запуск безопасен: `.env` и база не перезаписываются.

После запуска проверьте `https://ВАШ-ДОМЕН/health`. В DNS должна быть
A-запись на IP сервера, иначе Caddy не получит сертификат.

### Вариант Б — Docker

```bash
docker compose up -d --build
docker compose logs -f
```

Данные (SQLite) лежат в `./data` — смонтированы в том. Нужен внешний
reverse-proxy с HTTPS перед портом 8080.

### systemd вручную

```bash
sudo useradd -r -m -d /opt/ghostwriter ghostwriter
sudo -u ghostwriter git clone <repo> /opt/ghostwriter
cd /opt/ghostwriter && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env && nano .env
sudo cp deploy/ghostwriter.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now ghostwriter
journalctl -u ghostwriter -f
```

### Caddy вручную

```
bot.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

## 8. Ограничения Threads API, о которых стоит знать

- **500 байт** на текст поста, эмодзи считаются как UTF-8-байты (эмодзи = 4).
  Сервис проверяет длину до отправки и не даёт API вернуть ошибку.
- **250 постов за 24 часа** на профиль; дневной лимит сервиса по умолчанию
  ниже — 10.
- Текст обрабатывается асинхронно: после создания контейнера публикация может
  занять несколько секунд. Сервис умеет ждать готовности контейнера.
- **Токен живёт 60 дней**; продление работает, только пока токен не истёк.
  Если сервис стоял дольше — нужна повторная авторизация через `/token`.
- Ссылок в посте — не больше 5 (с 22.12.2025 иначе ошибка `LINK_LIMIT_EXCEEDED`).
- В Development mode постить можно только от имени Threads-тестировщиков
  приложения.
- API может отвечать `403` при первом вызове с новым токеном — повтор через

## 10. Диагностика

| Симптом | Что делать |
| --- | --- |
| Бот молчит | проверьте `TELEGRAM_BOT_TOKEN`, `/logs`, `journalctl -u ghostwriter` |
| «Нужна повторная авторизация» | `/token` → открыть ссылку |
| `OAuthException: Invalid redirect_uri` | `THREADS_REDIRECT_URI` ≠ URI в Meta (слэш, порт, http/https) |
| Пост не публикуется, «дневной лимит» | `/status`, поднять `max_posts_per_day` |
| Метрики пустые | у поста ещё нет просмотров или не выдано `threads_manage_insights`; метрики обновляются каждые 6 ч |
| Слот прошёл без публикации | проверьте `/queue`, паузу и режим через `/status`; пустая очередь пропускается штатно |
| Ошибка LLM 401 | `LLM_API_KEY` не соответствует `LLM_BASE_URL` |
